# Arya Shop Bot — پروژهٔ نهایی فروشگاه تلگرام

حل پروژهٔ `Last.pdf` با پایتون و مباحث دو پروژهٔ اولیهٔ کلاس: کلاس و شیء، `User` و `Product`، تابع و شرط و حلقه، `staticmethod`، مدیریت پیام و دکمه در `telebot`، پایگاه دادهٔ SQLite و تنظیمات `.env`.

**فایل اصلی اجرا: `app.py`. این پوشه یک مخزن واقعی Git با شاخهٔ `main` و commit اولیه است. هنوز در حساب GitHub یا Telegram شما منتشر نشده است.**

## شروع سریع

Python 3.10 یا جدیدتر نصب باشد. ابتدا ZIP را کامل استخراج کن و ترمینال را داخل پوشهٔ `arya-shop-bot` باز کن.

نصب کتابخانه‌ها، بدون تعیین نسخه:

```bash
python -m pip install pyTelegramBotAPI python-dotenv
```

یا به‌جای دستور بالا:

```bash
python -m pip install -r requirements.txt
```

`sqlite3`، `os`، `json`، `secrets`، `datetime` و `logging` همراه پایتون هستند. فایل تست از ابزارهای داخلی `unittest`، `tempfile` و `threading` هم استفاده می‌کند؛ نصب جداگانه لازم نیست. هیچ API قیمت بازار، درگاه پرداخت یا کتابخانهٔ رابط گرافیکی لازم نیست.

در صورت استفاده از چند نسخهٔ پایتون، نصب و اجرا را با همان مفسر انجام بده. در بعضی سیستم‌های ویندوز می‌توان `py` را جای `python` نوشت؛ در بعضی سیستم‌های لینوکس/macOS از `python3` استفاده می‌شود.

## تنظیم ربات و ادمین

1. با حساب خودت به [BotFather](https://t.me/BotFather) برو و `/newbot` بفرست. نام و نام کاربری آزاد انتخاب کن و توکن را بگیر.
2. فایل `.env.example` را کپی کن و اسم کپی را دقیقاً `.env` بگذار؛ نه `.env.txt`.
3. مقدار `TOKEN` را در `.env` وارد کن. دفعهٔ اول می‌توان `ADMIN_IDS` را خالی گذاشت.
4. اجرا کن:

```bash
python app.py
```

5. ربات را در تلگرام باز کن و در چت خصوصی `/id` بفرست.
6. عدد پاسخ را در `ADMIN_IDS` بنویس. آیدی متنی مثل `@aryaomidi1234` پذیرفته نمی‌شود. چند ادمین را با کاما جدا کن.
7. برنامه را با Ctrl+C ببند و دوباره اجرا کن. اکنون `/admin` پنل مدیریت را باز می‌کند.

نمونهٔ تنظیمات، با مقادیر جایگزین:

```dotenv
TOKEN=YOUR_BOTFATHER_TOKEN
ADMIN_IDS=YOUR_NUMERIC_TELEGRAM_ID
SHOP_NAME=فروشگاه آریا
DATABASE_PATH=shop.db
```

توکن واقعی فقط در فایل محلی `.env` یا متغیرهای محیطی سرور قرار می‌گیرد. دیتابیس شامل شماره‌ها و نشانی سفارش‌هاست؛ آن را عمومی نکن. `.env`، دیتابیس و محیط مجازی در `.gitignore` قرار دارند.

برای اجرا، اینترنتِ دارای دسترسی به Telegram لازم است. همین برنامه باید روی کامپیوتر یا سرور روشن بماند. فقط یک نمونهٔ برنامه با هر توکن اجرا کن. GitHub محل نگهداری کد است؛ به‌تنهایی ربات را روشن نگه نمی‌دارد.

## امتحان سریع با کالاهای نمونه

اختیاری؛ قبل یا بعد از اجرای اولیه، این دستور را در پوشهٔ پروژه بزن:

```bash
python seed.py
```

این کار فقط اگر هیچ کالایی در دیتابیس نباشد، ۶ محصول نمونه در سه دسته اضافه می‌کند. قیمت‌ها و کالاها آموزشی‌اند. برای فروشگاه واقعی، از پنل ادمین کالاهای خودت را بساز یا نمونه‌ها را ویرایش/حذف کن. هیچ کاربر، شماره، سفارش یا خرید ساختگی به دیتابیس اضافه نمی‌شود.

## مسیر استفادهٔ مشتری

1. `/start` و سپس دکمهٔ «ارسال شمارهٔ خودم». شمارهٔ Contact باید متعلق به همان فرستندهٔ پیام باشد.
2. «محصولات» ← دسته‌بندی ← محصول ← «افزودن یک عدد به سبد».
3. در «سبد خرید»، روی نام کالا بزن تا تعداد را کم/زیاد یا آن را حذف کنی.
4. «نهایی‌کردن سفارش» را بزن. کد تخفیف را وارد کن؛ اگر نداری، فقط `-` بفرست.
5. نام گیرنده و نشانی کامل را بنویس. خلاصهٔ مبلغ و نشانی را بررسی کن و «تأیید و ثبت سفارش» را بزن.
6. سفارش در «سفارش‌های من» و کد تخفیف جدید در «کدهای تخفیف من» دیده می‌شود.

نام یا بخشی از نام کالا را می‌توان مستقیم فرستاد یا از «جستجوی محصول» استفاده کرد. پیام «سلام» هم پاسخ خوش‌آمدگویی دارد.

برای کالای ناموجود، دکمهٔ «موجود شد خبرم کن» را بزن. با تغییر موجودی آن کالا از صفر به عدد مثبت، برای افراد متقاضیِ بلاک‌نشده اعلان ارسال می‌شود. این اشتراک پس از قرارگرفتن اعلان در صف مصرف می‌شود؛ برای نوبت بعد باید دوباره درخواست داد.

«پشتیبانی» هم ثبت تیکت و مشاهدهٔ تیکت‌ها و پاسخ‌ها را ارائه می‌کند. `/cancel` فرایند فعلی را لغو می‌کند. `/logout` از حساب خارج می‌شود و برای ورود دوباره اشتراک شماره لازم است. سبد، سفارش و سابقه با خروج حذف نمی‌شوند.

## پنل ادمین

فقط شناسه‌های عددی داخل `ADMIN_IDS` مجازند؛ شماره یا نام کاربری به‌تنهایی نقش ادمین نمی‌دهد.

- **افزودن محصول:** نام، دسته، توضیح، قیمت صحیح به تومان و موجودی صحیح. دستهٔ تازه خودکار ساخته می‌شود.
- **مدیریت محصولات:** ویرایش نام، توضیح، دسته، قیمت و موجودی؛ حذف با تأیید. با حذف، کالا از فروش و سبدها خارج می‌شود ولی جزئیات سفارش‌های قبلی می‌ماند.
- **مدیریت سفارش‌ها:** مشاهدهٔ اقلام و شماره و نشانی مشتری؛ تغییر وضعیت به‌ترتیب «در حال پردازش ← ارسال شده ← تحویل شده». هر تغییر اعلان مشتری دارد.
- **تیکت‌ها:** مشاهدهٔ سؤال و آخرین پاسخ؛ پاسخ‌دادن و بلاک/آنبلاک کاربر. مشتری پاسخ را در ربات و سابقهٔ تیکت می‌بیند.
- **مدیریت کاربران:** مشاهدهٔ وضعیت و بلاک/آنبلاک. حساب‌های ادمین از این پنل بلاک نمی‌شوند.
- **ارسال اطلاعیه:** نوشتن متن، دیدن پیش‌نمایش و تأیید ارسال به مشتریان ثبت‌نام‌شده و بلاک‌نشده.
- **پیام‌های معوق:** وضعیت ارسال اعلان‌ها و تلاش دوباره برای پیام‌هایی که مهلت انتظارشان گذشته است.

## تصمیم‌های مشخص در بخش‌های باز صورت سؤال

| موضوع | رفتار این نسخه |
|---|---|
| ثبت‌نام/ورود | اشتراک شمارهٔ همان حساب Telegram؛ بدون سرویس SMS یا رمز یک‌بارمصرف |
| خرید | ثبت سفارش با پرداخت هنگام تحویل؛ پول آنلاین کسر نمی‌شود |
| هزینهٔ ارسال | صفر، در سبد و پیش‌نمایش مشخص است |
| تخفیف بعد از خرید | بعد از ثبت موفق هر سفارش، کد شخصی ۱۰٪ برای خرید بعدی؛ ۳۰ روز اعتبار، یک‌بارمصرف |
| جمع تخفیف‌ها | فقط یک کد در هر سفارش؛ تخفیف به تومان صحیح رو به پایین گرد می‌شود |
| موجودی | در سبد رزرو نمی‌شود؛ هنگام تأیید سفارش دوباره بررسی و کم می‌شود |
| تغییر قیمت/سبد | پیش‌نمایش قبلی پذیرفته نمی‌شود؛ مشتری باید دوباره بررسی کند |
| سبد | حداکثر ۲۰ محصول متفاوت و حداکثر ۹۹ عدد از هر محصول، در حد موجودی |
| مهلت فرم | مراحل ثبت محصول/تیکت/خرید تا ۲ ساعت نگهداری می‌شوند |
| گروه‌ها | عملیات فقط در چت خصوصی ربات انجام می‌شود |
| حذف محصول | حذف منطقی؛ جزئیات قیمت و نام زمان خرید در سفارش باقی می‌ماند |
| لغو سفارش پرداخت‌شده | در صورت سؤال نیست؛ این نسخه مسیر لغو یا استرداد وجه ندارد |

تغییر درصد/اعتبار تخفیف در متد `checkout` فایل `database.py` ممکن است. واحد قیمت همه‌جا تومان است.

## خطاهای ارتباط و اعلان‌ها

ثبت سفارش و صف اعلان در دیتابیس ذخیره می‌شوند. قطعی ارسال پیام، سفارش موفق را حذف نمی‌کند. اعلان موقتاً ناموفق بعد از مهلت مقرر، در شروع مجدد برنامه، با دریافت پیام بعدی یا دکمهٔ «پیام‌های معوق» دوباره بررسی می‌شود. برای نرخ زیاد، این نسخه worker جداگانه ندارد. خطای دائمی مثل مسدودکردن ربات توسط گیرنده در شمارندهٔ ناموفق دیده می‌شود. ارسال شبکه ممکن است در حالت قطع ارتباط پس از تحویل، تکرار شود؛ برای جلوگیری از خرید دوباره همیشه شمارهٔ سفارش را ملاک قرار بده.

پردازش پیام‌ها با `threaded=False` انجام می‌شود تا اتصال SQLite در یک نخ بماند. تراکنش سفارش، بررسی موجودی، مصرف کوپن، صدور کوپن جدید و پاک‌کردن سبد با هم انجام می‌شوند. قیمت‌ها عدد صحیح هستند. دوبار کلیک روی تأیید، سفارش دوم نمی‌سازد.

## ساختار و ارتباط با دو پروژهٔ کلاس

| فایل | مسئولیت | مبنای آشنا از کلاس |
|---|---|---|
| `app.py` | خواندن تنظیمات و اجرای ربات | `shop_bot/app.py` |
| `handler.py` | مسیرهای مشتری و پیام‌ها | `shop_bot/handler.py` |
| `admin.py` | پنل ادمین و ورودهای مرحله‌ای | `AdminTelegramBot` |
| `buttons.py` | کیبوردهای Reply و Inline | `Buttons` و `staticmethod` |
| `database.py` | SQLite، سبد، سفارش، تخفیف، تیکت و موجودی | کلاس `Database` در دو پروژه |
| `models.py` | کلاس‌های `User` و `Product` و اعتبارسنجی | مدل‌های `saghf` |
| `service.py` | خدمات فروشگاه، گزارش سفارش و ارسال اعلان | جداسازی خدمات از مدل‌ها |
| `seed.py` | دادهٔ نمونهٔ اختیاری | ساخت شیء و افزودن داده |
| `test.py` | آزمون‌های خودکار توسعه | ابزار داخلی پایتون؛ لازم برای اجرای ربات نیست |

برای کامل‌شدن صورت سؤال، جدول‌های سفارش، تیکت، تخفیف و وضعیت مراحل به الگوی پروژه‌های کلاس اضافه شده‌اند. کتابخانهٔ بیرونی تازه‌ای لازم نشده است. به‌جای یک متغیر مشترک مثل `self.name` برای همهٔ کاربران، مرحلهٔ هر کاربر جداگانه در SQLite نگهداری می‌شود تا ورودی مشتریان با هم قاطی نشود.

## مخزن Git و ارسال به GitHub

داخل فایل ZIP، پوشهٔ مخفی `.git` نیز وجود دارد. آن را همراه پروژه استخراج کن؛ **لازم نیست دوباره `git init` بزنی**. بررسی:

```bash
git status
git log --oneline
```

در GitHub یک repository خالی بساز؛ هنگام ساخت آن README یا gitignore جداگانه اضافه نکن. سپس مقادیر نمونهٔ زیر را با نام کاربری و نشانی مخزن خودت جایگزین کن:

```bash
git remote add origin https://github.com/YOUR_USERNAME/arya-shop-bot.git
git push -u origin main
```

این فرمان نیاز به ورود معتبر GitHub روی دستگاه خودت دارد. توکن GitHub را در فایل کد یا نشانی remote ننویس. اگر `origin` از قبل وجود داشت، با `git remote -v` بررسی کن و فقط در صورت درست‌بودن مخزن، `git remote set-url origin ...` را به‌کار ببر.

commit اولیه با نام `Codex` ثبت شده است. برای تغییرات بعدی، نام و ایمیل GitHub خودت را در همین مخزن تنظیم کن:

```bash
git config user.name "YOUR_NAME"
git config user.email "YOUR_GITHUB_EMAIL"
git add .
git commit -m "Update shop bot"
git push
```

در روش آپلود دستی از سایت GitHub، فایل‌های سورس و مستندات را آپلود کن؛ پوشهٔ `.git` برای خود Git است و آپلود دستی آن لازم نیست. `.env` و `shop.db` را در هیچ‌یک از روش‌ها منتشر نکن.

## رفع اشکال نصب

دستور `pip install` را در Terminal / CMD / PowerShell بنویس، نه داخل فایل پایتون یا جلوی `>>>`.

برای بررسی مفسر و pip:

```bash
python --version
python -m pip --version
```

اگر ماژولی پس از نصب پیدا نشد، مفسر انتخاب‌شده در PyCharm/VS Code را با مفسری که نصب را انجام داده یکسان کن. خطای شبکه یا SSL را با متن کاملش بررسی کن؛ اعتبارسنجی TLS را خاموش نکن.
